## 一、机制（来源：MiniApp 天机阁 `command-center` 真实回包 + `dwelling.companions[].raw` 时间戳 + 群内官方回复）

**入口**：洞府 MiniApp `POST /api/miniapp/xianxia-dwelling/command-center {"command": ".xxx"}`。
白名单包含 `.我的侍妾 .远航状态 .远航归来 .侍妾远航 <稳妥|均衡|冒险|月殿寻痕> .天机代卜 .入梦寻图 .残图 .拼图 .坠魔心劫 .召回侍妾 .安置侍妾`。
所有指令作用于**随行中**的侍妾；`.召回侍妾 <名字>` 即时切换，"情缘、神通与冷却均保持不变"（本次已验证，含远航中切换）。
`.共历心劫`（三轮 稳/狠/骗，+600~860 修为 +7 情缘 −5 心魔，**600 分钟**）被 MiniApp 目录标为 `group_only`：必须在群里回复消息。
本流程已把它并入循环（`pavilion_loop/heart_trial.py`）：发 `.我的侍妾` → 回复该状态卡发 `.共历心劫` → 机器人回 `【坠魔心劫·第一轮】` →
对同一条锚点消息连续回复三次 `.稳`。机器人**原地编辑锚点**，且轮次标签在首轮后改用阿拉伯数字（真实文本，2026-09-21 核对）：
第 1 次 `.稳` → `【坠魔心劫·第1轮已定】…【坠魔心劫·第2轮】幻境再变，请继续回复 .稳 / .狠 / .骗。`；
第 2 次 → `【坠魔心劫·第2轮已定】…【坠魔心劫·第3轮】…`；第 3 次 → `【坠魔心劫·结算】 三轮抉择：稳 / 稳 / 稳 …`。
09-21 白天的回归（每个账号只回了一次 `.稳`）就是分类器只认“第二轮/第三轮”中文数字导致的；现在 `classify_trial` 同时识别中文与阿拉伯数字，
并且按锚点**文本状态**推进（编辑没到位就再补一次 `.稳`，最多 5 次；全 稳 路线补发不会选错）。回复错消息会得到 “心劫锚点已散”，
机器人若以新消息而非编辑回应，链会立即停止并记录该回复。
半途丢下的心劫会让账号后续 `.共历心劫` 一律被拒（“你已有一场心劫抉择正在进行，请先完成当前抉择。”）：
流程会回溯本账号最近的 `.共历心劫` 找到仍处于轮次状态的锚点，先把它 稳 到结算（`resumed_settlement`），再开本次心劫。
稳/稳/稳 为收益最大路线（“韩立式谨慎贯穿全局，收益最大”）。远航中被拒（“暂不可共历心劫”），故在再远航之前执行。

## 二、最佳循环

远航会阻塞代卜 / 寻图 / 坠魔心劫 / 共历心劫，因此每位侍妾的周期是：**归航 → 代卜 → 寻图 → 坠魔心劫 → 共历心劫（群内）→ （拼图）→ 再远航**。
选 **均衡 8 小时** 航线，与 480 分钟寻图冷却对齐：每 8 小时归航一次，寻图恰好可用；代卜与心劫（720 分钟）每两轮做一次。
双侍妾：先跑随行者，再 `.召回侍妾` 常住者跑同一序列，最后召回原随行者（保持用户原设置）。
新侍妾情缘 < 30 时任何航线都被拒（“至少需要 30 情缘值”），只能靠 共历心劫（+7）攒情缘，流程记 `affection_too_low_to_sail` 并等待下一个计时器；30–69 走 **稳妥 4h**，达到 70 后自动切均衡（服务器拒绝时也会当场回退一次稳妥）；**@demo_player_01 的 南宫婉·月影 固定走 月殿寻痕 6h**（用户 09-21 规定，`ROUTE_OVERRIDES` 钉死，任何拒绝都不改航线）；其他账号的南宫婉按名字默认月殿寻痕；可在 `pavilion_loop/state.py::ROUTE_OVERRIDES` 按账号/侍妾改航线。
**@demo_player_01 的温天心已按用户2026-10-05要求恢复自动远航**，替代2026-09-22的暂停规则。
已从 `pavilion_loop/state.py::NO_SAIL` 移除该限制，沿用普通航线选择：情缘≥70走均衡8小时，
30–69走稳妥4小时；其他步骤、冷却及南宫婉·月影固定月殿寻痕的规则保持。

## 三、实现

- `pavilion_loop/protocol.py` 冷却常量、回包分类（归航 / 代卜卦 / 寻图得失 / 心劫护持 / 冷却剩余 / 远航中拒绝）、航线选择。
- `pavilion_loop/runner.py` 每账号：读 `dwelling.companions` 时间戳 → 双侍妾依序执行到期步骤 → 每步只认 `actionResult`
  与刷新后的时间戳 → 各侍妾 `next_due_at` 取最早服务器计时器（最长 4 小时复查）。
- LaunchAgent `ai.hermes.xiuxian.pavilion-loop.send`：10 分钟 tick（到期才登录），串行六账号；13:36–13:52 让路青元子。
- 状态 `state/accounts/<账号>/pavilion_loop/state.json`，汇总 `state/pavilion_loop/summary.json`；
  每批有操作时通过 Hermes 发 `【藏娇阁】` 汇总（归航收益 / 卦象 / 寻图得失 / 心劫 / 航线）。
- 离线测试 `pavilion_loop/test_pavilion_loop.py`（回包全部为真实文本）；`--check` / `--dry-run` 可只读验证。

## 五、限制与迭代提示

- `.共历心劫` 走群内回复链，依赖官方机器人原地编辑锚点消息；若机器人改为新消息回复，需调整 `heart_trial.wait_edit`。
  轮次文案只在 `heart_trial.classify_trial` 里补（中文/阿拉伯数字都已覆盖），判据是锚点文本到达 `【坠魔心劫·结算】`，不是自己数发了几次。
- 洞府 MiniApp 入口（`【洞府公共入口】` 按钮，`hantianzunNN_bot?startapp=df_…`）约 30 天轮换一次，2026-09-21 已从 `@example_game_group`
  置顶迁到游戏群 `-1009400000005` 的置顶消息。入口发现在 `fishing/miniapp_fishing_integration.py::_dwelling_entry_candidates`：
  扫两群的置顶 + 近 300 条带机器人按钮的入口公告，取最新；`miniapp_shared/dwelling.py::open_dwelling` 按新→旧逐个试，
  服务器回 `dwelling_token_missing` 等即换下一个。最近一次成功的入口只记消息引用到 `state/dwelling_entry_cache.json`（不存 token）。
  再换入口无需改代码；若六账号同时报 `dwelling_entry_failed`，先看两群置顶是否还有入口按钮。
- 代卜卦是随机的；如需“先代卜得残图引路再寻图”，顺序已保证代卜先于寻图，但不保证卦象。
- 冒险航线的情缘损失会影响侍妾神通，默认不用；需要养魂木时用 `ROUTE_OVERRIDES`。
- 新的服务器文案只在 `protocol.classify` 里补；不要凭猜测改冷却常量，用 `--dry-run` 的 `*_in_min` 与 `.我的侍妾` 剩余分钟核对。
